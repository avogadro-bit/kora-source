# Kodachrome 64 — experimental special film (0.2.42)

## Use

Open a supported RAW, then choose **Kodachrome 64 · Experimental** in
**FILM SIMULATION**, alongside the Fujifilm choices. It is built into Kora.
The first-run Fujifilm setup dialog can be closed when using this film alone.
Start with a new recipe, Camera white balance, Push / Pull 0, DR 100, no tone,
color or grain adjustments. Adjust Push / Pull to the photograph, then use the
usual JPEG or TIFF export. C1–C7 and JSON recipes retain the film choice.
PROVIA remains the application default. Selecting a film retains your other
recipe settings; existing adjustments therefore change the experimental look.

Push / Pull **0** corresponds to the study's conventional **+0.5 EV** anchor.
For example, −1 in Kora corresponds to −0.5 EV in the standalone study, and
+1 in Kora corresponds to +1.5 EV. The anchor is not a sensitometric calibration.
There is no additional exposure gain after the film. Kora's optional grain and
other effects remain artistic controls; no MTF or measured K64 grain is added.

## Model and scope

The color transform reuses the model developed from the three non-MTF plots
on page 4 of Kodak E-88 (June 2009). Characteristic RGB curves and normalized
dye spectra determine dye amounts and transmission. Scene RGB is interpreted
as linear sRGB under D65. Reflectance reconstruction minimizes the squared
first derivative (the study's “pente” method), subject to color matching and
reflectance in [0,1]. Spectral sensitivities outside the plotted domain are zero;
dye absorption outside its plotted domain holds the nearest plotted value.
Observation uses CIE D50 with full Bradford adaptation to sRGB D65. The film's
base transmission is not neutralized.

This is an **experimental reconstruction** of published plots, not original
Kodak measurements, a calibrated camera profile, a measured scan transform, or
an exact reproduction of a Kodachrome slide. No fit to the small Film2Paint
illustration or five selected patches is promoted into a general calibration.
RGB-to-spectrum inversion is non-unique. Kora's RAW development, source white
balance, exposure normalization and input color refinements precede this film;
they differ from the standalone DNG script. Identical RAW files therefore need
not produce identical pixels across those two applications.

Kora can carry negative RGB components and values above one. The model adapter
clips negative components to zero. For RGB above one, it separates an intensity
factor equal to max(1, max RGB), reconstructs the normalized RGB, and multiplies
layer responses by the same factor. This is an explicit HDR extension, not a
measurement of scene reflectance. User exposure is applied to layer responses
after reconstruction, matching the study. Values outside the digitized logH
range hold the curve endpoints. Final display colors are clipped to sRGB.

## Fast evaluation and reproducibility

`kora/film_data/kodachrome64_v1.npz` contains two 65³ tables and the original
interpolated characteristic/colorant arrays. The first table stores layer
responses from constrained spectral reconstruction. Its grid is spaced in
encoded sRGB for dark-tone precision, but tetrahedral interpolation fractions
are evaluated on the decoded **linear** axis. The second table integrates dye
transmission under D50 and uses trilinear interpolation. Exposure remains
outside the first table, so this is not a single fixed-exposure RGB look.
All preview, detail-tile and export paths call the same implementation.
Rows are processed in bounded blocks; the application never creates a full
photograph-sized spectral cube. The scientific-table checksum is checked at
load. Source hashes, axes, assumptions and dye-table accuracy are recorded in
the accompanying JSON manifest.

From the project directory with NumPy, SciPy, Pillow and rawpy installed:

```sh
OPENBLAS_NUM_THREADS=1 python scripts/build_kodachrome_model.py
python scripts/validate_kodachrome.py --write-reference
python scripts/validate_kodachrome.py
python -m unittest discover -s tests -v
node --test tests/*.cjs
```

The build takes several minutes because it solves the bounded spectra directly.
The test reference is generated by full constrained reconstruction and direct
spectral integration, independently of the fast runtime tables: 160 input
colors, including dark neutrals and cube corners, at seven exposure offsets.
This measures numerical agreement with the prototype, **not accuracy against
physical film**. The detailed local validation report is supplied with the build.

The four reference Python modules are retained from the standalone study.
Their data and attributions are included under `scripts/kodachrome_reference`.
The source attribution file omits the private photo-folder path; no photographs
are embedded in either the model or source distribution.
